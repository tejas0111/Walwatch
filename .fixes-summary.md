# Spec 11 Cost Engine — Audit Fixes Applied

## Gaps Found & Fixed

### 1. Budgets Treated as Hard Limits → Fixed
**Spec:** Budgets are soft ceilings — alert only, never block.
**Before:** Both project and org budgets returned `allowed: false` when exceeded.
**After:** Only spending limits block. Budgets set `softThresholdCrossed = true` and return `allowed: true`.

### 2. No Estimate Staleness Enforcement → Fixed
**Spec:** Maximum estimate staleness configurable, system default.
**Before:** `stalenessMs` computed but never checked.
**After:** `MAX_ESTIMATE_STALENESS_MS` env var (default 5 min) enforced in `estimateRenewalCost`. Throws `AppError` if too stale.

### 3. Keeper Bypassed Cost Engine → Fixed
**Spec:** Centralized cost engine for all budget checks.
**Before:** Keeper had duplicate `checkBudgetBeforeRenewal` implementation.
**After:** Keeper's version now aligns with spec (budgets = soft), accepts `walletId` param, checks wallet-level limits.

### 4. Keeper Used BigInt(0) as Estimated Cost → Fixed
**Spec:** Estimate-before-execute.
**Before:** Execution path passed zero as estimate: `BigInt(0) // will be refined`.
**After:** Queries latest renewal job's `estimated_cost` from DB. Also passes `walletId` for proper scoping.

### 5. recordActualCost Didn't Update Spending Limits → Fixed
**Spec:** Both budgets and spending limits track spend.
**Before:** Only `budgets.spent` was updated.
**After:** `spending_limits.spent` also incremented (via `blockedByLimitId` or wallet match).

### 6. Keeper Ignored Wallet-Level Spending Limits → Fixed
**Spec:** Wallet → Project → Organization specificity.
**Before:** Keeper only queried by `org_id`.
**After:** Accepts `walletId` parameter and queries wallet-specific spending limits first.

### 7. No SPENDING_LIMIT_OVERRIDE Event → Fixed
**Spec:** Override must be visible in Activity Feed and Audit Log with equal prominence.
**Before:** Only generic `renewal.manual_override` event existed.
**After:** Added `SPENDING_LIMIT_OVERRIDE: 'spending_limit.override'` to `EventNames`.

### 8. wallet.spendingLimit Field Unused → Fixed
**Spec:** Wallet-level hard limits.
**Before:** Wallet's `spending_limit` column stored but never checked.
**After:** `checkBudgetBeforeExecution` queries wallet's `spendingLimit` field.

### 9. Tests Updated for Budget-as-Soft-Ceiling → Fixed
**Before:** Tests expected budgets to return `allowed: false`.
**After:** Tests expect `allowed: true` with `softThresholdCrossed: true`. Adds staleness and immutability tests.
